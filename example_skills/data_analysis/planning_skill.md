# Data Analysis Planner Skill

## Purpose

사용자의 모호한 데이터 분석 요청을 실행 가능한 분석 계획으로 구체화한다. 이 스킬은 Planner A처럼 최초 계획을 세우는 에이전트에게 맞춘다.

## Shared Data Analysis Checklist

- 데이터의 분석 단위를 먼저 파악한다. 한 행이 사람, 거래, 기업, 지역, 시점, 문서, 제품 중 무엇을 의미하는지 확인한다.
- 열의 의미, 단위, 타입, 시간 범위, 식별자, 범주형 값의 불일치를 확인한다.
- 결측치, 중복, 비정상 값, 인코딩 문제, 파싱 실패를 분석 전 단계에서 기록한다.
- 시간 변수가 있으면 시간 흐름, 변화율, 계절성, 구조적 변화 가능성을 검토한다.
- 수치형 변수는 평균만 보지 말고 중앙값, 분위수, 분산, IQR, 최소/최대, 분포 형태를 함께 확인한다.
- 왜도가 큰 변수는 로그 변환, 분위수 비교, robust summary를 고려한다.
- 이상치는 무조건 삭제하지 않는다. 탐지 기준, 영향, 제외 전후 차이를 설명한다.
- 비교 분석에서는 분모, 노출량, 집단 크기, 관측 기간, 표본 수 차이를 확인한다.
- 상관관계와 인과관계를 구분한다. 관찰 데이터로 인과를 단정하지 않는다.
- 모든 결론에는 데이터 한계, 가정, 불확실성을 함께 적는다.

## Planner Guidelines

- 첨부 데이터가 있으면 `input_manifest`만 보지 말고 원본 파일을 직접 열어본다.
- 계획 상단에 `Data Inspection Notes`를 포함한다:
  - 확인한 파일, 시트/테이블, 행 수, 열 수
  - 분석 단위
  - 주요 식별자, 시간 변수, 핵심 수치형/범주형 변수
  - 시간 범위, 결측/중복/이상치 후보
  - 단위나 인코딩이 불확실한 컬럼
- 사용자의 요청을 분석 질문으로 다시 쓴다.
- 누가 결과를 보고 어떤 결정을 내릴지 추정하되, 확실하지 않으면 가정으로 표시한다.
- 최소한 다음 분석 관점을 검토한다:
  - 데이터 품질
  - 기술통계
  - 분포
  - 집단 간 비교
  - 시간 흐름
  - 관계/상관
  - 이상치와 민감도
  - 해석 한계
- 지표를 정의할 때 분자, 분모, 단위, 집계 수준을 명시한다.
- 단순 순위표나 KPI 카드만으로 끝내지 말고, 왜 그런 결과가 나왔는지 확인할 수 있는 보조 분석을 포함한다.
- 산출물이 대시보드라면 필터, 정렬, 상세 테이블, 원자료 검산 경로를 계획한다.
- 시간 변수가 존재하면 최소 하나 이상의 시계열 뷰를 계획한다. 명시적으로 부적절한 경우에만 제외 사유를 적는다.
- 기본 화면이 극단 이상치나 소표본 집단에 지배되지 않도록 합리적인 기본 필터와 해제 옵션을 계획한다.
- 필터는 가능하면 숫자 직접 입력만 두지 말고 사용자가 이해하기 쉬운 프리셋을 함께 제공한다.
- 차트가 많으면 긴 스크롤 나열 대신 탭, 세그먼트, 접기/펼치기 등 탐색 구조를 계획한다.
- 좋은 결과물의 기준을 기능 기준과 분석 기준으로 나눈다.
- 불확실한 도메인 지식은 단정하지 않고, 사용자 확인이 필요한 질문이나 가정으로 남긴다.
