# Data Analysis QA Skill

## Purpose

생성된 분석 결과물, 대시보드, 리포트, 코드가 데이터 분석 관점에서 신뢰할 만한지 검토한다.

## Shared Data Analysis Checklist

- 데이터의 분석 단위, 열 의미, 단위, 타입, 시간 범위, 식별자, 범주형 값의 불일치를 확인한다.
- 결측치, 중복, 비정상 값, 인코딩 문제, 파싱 실패가 기록되었는지 확인한다.
- 시간 변수가 있으면 시간 흐름, 변화율, 계절성, 구조적 변화 가능성을 확인한다.
- 수치형 변수는 평균뿐 아니라 중앙값, 분위수, 분산, IQR, 최소/최대, 분포 형태를 함께 확인해야 한다.
- 왜도가 큰 변수와 이상치가 결과를 지배하는지 확인한다.
- 비교 분석에서는 분모, 노출량, 집단 크기, 관측 기간, 표본 수 차이를 확인한다.
- 상관관계와 인과관계를 구분한다.
- 모든 결론에 데이터 한계, 가정, 불확실성이 포함되는지 확인한다.

## QA Guidelines

- 결과물이 실행되는지만 보지 말고, 분석이 타당한지 확인한다.
- 데이터 로딩 결과가 원본 파일과 일치하는지 확인한다.
- 행 수, 열 수, 주요 컬럼, 결측치 요약이 표시되거나 문서화되어 있는지 확인한다.
- 핵심 지표 계산식을 샘플 행 또는 간단한 재계산으로 검산한다.
- 시간 변수가 있는데 시간 흐름 분석이 빠졌다면 PASS로 처리하지 않는다. 요구 목적상 치명적이면 FAIL, 보조 기능이면 PASS_WITH_WARNINGS 또는 INCONCLUSIVE로 판단한다.
- 집단 비교가 있는데 표본 수, 분모, 관측 기간 차이를 무시했다면 문제로 지적한다.
- 왜도가 큰 수치형 변수를 평균만으로 설명하면 문제로 지적한다.
- 이상치가 결과를 지배할 수 있는데 탐지나 민감도 분석이 없으면 문제로 지적한다.
- 기본 화면이 소표본 집단이나 극단 이상치에 지배되는지 확인한다.
- 필터, 정렬, 검색, 차트 상호작용이 실제 계산 결과에 반영되는지 테스트한다.
- 대시보드가 사용자의 의사결정에 도움이 되는 기본값과 탐색 흐름을 제공하는지 확인한다.
- 시각화가 잘못된 인상을 주는지 확인한다:
  - 축 절단
  - 부적절한 누적
  - 과도한 색상
  - 3D/장식성 차트
  - 비교 불가능한 값을 나란히 배치
- 결론이 데이터가 뒷받침하는 범위를 넘어 인과나 가치판단으로 비약하지 않는지 확인한다.
- 윤리적으로 민감한 변수나 집단 비교가 있으면 편향, 낙인, 차별적 해석 가능성을 점검한다.
- 최종 QA는 PASS, PASS_WITH_WARNINGS, FAIL, INCONCLUSIVE 중 하나로 판단하고, 판단 근거를 데이터 품질, 계산 정확성, 분석 타당성, 시각화, 윤리/해석 리스크로 나눠 적는다.
